# Graph output selection audit

Read-only source review, 2026-10-29. Runtime source identity: `71e9e24fa4cf376e6292421863bc3b5d624d65a9a9153b0c08579d8ed6974da1`. No inference, server changes or production edits were made for this audit. Recommendations below are proposed work, not implemented capabilities or an acceptance result.

**Finding:** the current app cannot select a subset of OCR observations after recognition and publish only that subset. It can crop the image supplied to a reader, but that changes recognition input. Two independent capabilities are missing: selecting observations and explicitly choosing application outputs. Adding only a text filter would not fix the current output accumulator.

## Verified behavior

| Behavior | Source evidence and consequence |
| --- | --- |
| Every executed text producer contributes to the frame output. | `engine/runtime/executor.py:63–86` appends every `TextValue.texts`, then removes duplicate strings. This includes all OCR/barcode branches and, in the lower-level runtime, VLM labels. A consumer or event sink is not required. |
| `match` is a check, not extraction. | `executor.py:91–100` compares the entire text list, saves all observed strings in `TextComparison`, and optionally suppresses its event. Its only port is `event` (`engine/blocks/registry.py:55–56`). `contains` searches a space-joined list; it is not a per-reading selector. |
| Structured evidence already exists. | `spec/inference.py:49–53,82–108` retains each raw reading's literal text, nullable geometry/confidence, reader identity, input-pixel hash and source transform. `engine/runtime/values.py:32–35` exposes only strings plus one optional whole-inference pointer at the text port. There is no selected-reading lineage. |
| Image cropping is a different operation. | `executor.py:173–184` changes the pixels passed down that image branch. It does not erase the saved source image, but it cannot express “recognize the entire image, then return these observations.” |
| UI and scoring follow the same accumulated output. | Native `ReadingEvidenceDTOs.swift:90–104` displays `frame.texts` separately from all raw reading overlays. `InvestigationViews.swift:109–114` does the same for drafts. `engine/eval/__init__.py:83` scores `result.texts`; `engine/eval/recipe.py:81–82` explicitly warns about the deduplicated union. |

The A0 contract already explains that OCR reads all text and `match` cannot filter it (`agent/investigation_docs.py:22–26`). The failed full-frame OCR+match draft therefore contains both a product limitation and an incorrect model decision: checking a label does not extract its value. Later successful probes also did not revise that saved graph. Conversely, asking for an unavailable filtering operation can identify a real capability gap; asking the user for an arbitrary regex does not establish that regex is the right solution. New primitives will not themselves solve field interpretation, layout generalization or the decision to rebuild a draft.

## Smallest coherent implementation

1. **`select_text`: a pure `text → text` observation selector.** Keep original order and literal strings, including duplicate observations. Preserve `(source_block_id, reading_index)` lineage through successive selections; resolve geometry through the immutable `BlockInference` and `input_to_frame`. Start with a small discriminated predicate contract: per-reading literal equality/contains and a normalized source-frame region with an explicit center-inside rule. Missing geometry must have explicit behavior, never fabricated coordinates. Predicates are graph parameters chosen by the agent/user, not host task-word rules. Do not infer a confidence threshold or normalize text implicitly.
2. **`output_text`: an explicit, effect-free terminal output binding.** Its text input defines application output; it neither generates events nor alters raw inference evidence. With one or more explicit output bindings, compute `frame.texts` only from those bindings after execution. Empty selected output stays empty—never fall back to all OCR. Preserve the current deduplicated union for old graphs without explicit outputs. For new explicit outputs, preserve order and duplicates and expose a typed per-output receipt containing the output block/source reference and reading lineage. Multiple bindings must have deterministic ordering, independent of incidental topological scheduling.

These can share the existing `text` port; a new reader adapter or replacement OCR model is unnecessary. Extend the internal value with lineage rather than copying a filtered list into `InferenceResult.readings`. Only the original inference node should append a `BlockInference`; carrying its existing `inference` pointer unchanged through every selector would append duplicate raw evidence at `executor.py:74–75`.

A regex predicate is an optional extension for format-based selection, **not** the output-binding fix. Add it only with explicit full-match/search semantics, bounded inputs/patterns and a bounded-time implementation; unrestricted Python backtracking regex is inappropriate for model-generated patterns. Do not silently turn “read the requested field” into a hard-coded value or regex. Anchor-relative spatial relationships/dynamic field extraction remain separate extensions; a static region is only a layout hypothesis and needs shifted-layout counterexamples.

## Counterfactual tests required before a live planner retry

- Same full-image inference with four distinct readings: switch selection/output wiring and observe a different published subset **without** changing OCR call count, input pixel hash, raw readings, geometry or identity. Include a second non-published reader to catch the current accumulator bug.
- Run `match` with each event policy: the original readings remain unchanged. Add `select_text → output_text`: output changes while comparison/event semantics remain independent and no event is persisted.
- Select zero readings: explicit output is empty although raw OCR is nonempty. Remove explicit outputs: historical union/dedup behavior returns unchanged. Decode both old and new receipts in Swift.
- Repeated identical strings at distinct locations and decomposed Unicode/whitespace survive selection and output with distinct lineage. Two chained selectors must not reindex lineage or duplicate inference receipts.
- Geometry selection after crop+resize maps through the actual transform; test just-inside/outside boundaries and missing boxes. Move the field outside a static region: the test must reveal the failure, not silently move the region or substitute an expected answer.
- Two explicit outputs/branches retain deterministic order under a reordered valid graph; wrong references, invalid predicates and cycles fail compilation. If regex ships, include invalid and adversarial patterns under the real execution deadline.
- Change only the selector or output source: spec/task identities change and earlier scores cannot be reused as equivalent evidence. Saved preview, paged inspection, selected-workflow context and native output agree on the exact subset; all raw evidence remains accessible.
- A fresh planner must choose an applicable selector and construct a new saved revision, then assess that revision's actual preview. Test new strings/layouts with withheld references. A successful filter demonstration or scripted graph is not proof of this adaptive behavior.

Recommended next slice: implement the selector, explicit output binding and lineage together; validate software counterfactuals first, then one bounded live construction test. Keep dynamic field association and generic regex as explicit follow-on scope unless independently justified.
